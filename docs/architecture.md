# 架构约定

## 部署边界

```text
笔记本浏览器
    │ HTTP：配置与操作请求；WebSocket：状态与事件
    │ 以太网
    ▼
RK3566 Linux
    ├── 网页静态资源与 API
    ├── 唯一设备控制入口、命令队列与任务状态机
    ├── USB 相机采集与 OpenCV 视觉
    └── 下位机通信适配层
            │ 通信接口与协议待定
            ▼
        下位机 MCU
            └── 实时运动、IO、限位与故障保护
```

网页刷新不重新创建贴装任务。机器状态和执行进度由板端管理，网页不能直接绕过控制服务操作下位机。

相机由统一采集模块持有。采集、视觉计算与网络请求处理分离，队列有界；定位必须验证图像与运动状态的时序，不能仅凭读取时间认定曝光发生在停稳之后。

下位机回复须区分命令接收与动作完成。通信协议应明确命令编号、错误返回、超时、重复命令处理以及停止行为。硬件急停不依赖浏览器或 Linux 服务。

## 仓库边界

- `console` 不依赖固件源码，仅依赖公开 API 约定。
- `controller` 通过通信适配层访问下位机，不在业务代码中散布串口或总线读写。
- `firmware/mainboard` 独立构建，不依赖网页运行环境。
- `protocols` 保存可跨语言阅读的协议定义；必要时再增加代码生成。
- 配置示例与设备实测标定数据分开，后者保存于已忽略的 `local/` 并另行备份。
- 硬件文件和软件可以一起提交，但软件构建不应下载或解析全部 CAD 文件。

## 版本与部署

各模块可独立构建和部署。整机发布说明应记录 Git 提交、硬件修订、系统镜像版本、控制服务版本、固件版本和通信协议版本。

应用更新不要求重刷 Linux；固件更新按下位机烧录流程执行。控制服务启动时核对下位机协议兼容性，进程重启后重新确认设备状态，不自动续跑未完成动作。
